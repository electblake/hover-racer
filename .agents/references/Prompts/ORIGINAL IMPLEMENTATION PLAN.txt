# HOVER RACER — CODEX IMPLEMENTATION PLAN

**Project:** Hover Racer Web  
**Target:** HTML5, JavaScript, Three.js  
**Reference:** Original Godot 4.7 project in `Video Game.zip`  
**Objective:** Faithfully port the existing 3D hover-racing prototype to the browser.

## 1. Agent Role and Operating Instructions

You are the lead gameplay and graphics engineer responsible for recreating Hover Racer using Three.js.

Your priority is **behavioural fidelity to the original Godot project**, not creating a new racing game.

You must:

1. Inspect the original project before implementing each subsystem.
2. Treat the current Godot scripts and scenes as authoritative.
3. Preserve original physics values, input processing, track geometry, camera behaviour, and vehicle design.
4. Implement the project incrementally in independently testable modules.
5. Keep all gameplay tuning values centralized.
6. Use deterministic fixed-timestep gameplay updates.
7. Write automated tests for numerical behaviour.
8. Maintain a runnable browser build throughout development.
9. Avoid adding new gameplay features without explicit authorization.
10. Document unavoidable differences between Godot and browser behaviour.

Do not substitute generic arcade-racing physics for the original implementation.

Do not silently alter speed, turning, acceleration, braking, road dimensions, or camera behaviour to make the game easier.

When source files are ambiguous, document the uncertainty and favour the implementation matching the original game.

## 5. Implementation Phases

### Phase 1 — Project Bootstrap

Tasks:

1. Initialize Vite with JavaScript.
2. Install Three.js, Vitest and Playwright.
3. Create the rendering canvas.
4. Configure resize handling and device pixel ratio.
5. Add a perspective camera, ambient lighting and directional lighting.
6. Create a fixed-timestep accumulator.
7. Add basic error reporting and development diagnostics.
8. Add `npm run dev`, `npm run build`, `npm run test` and `npm run test:e2e`.

Fixed update loop:

```js
const STEP = 1 / 60;
let accumulator = 0;
let previousTime = 0;

function frame(timestamp) {
  if (previousTime === 0) previousTime = timestamp;

  const elapsed = Math.min(
    (timestamp - previousTime) / 1000,
    0.25
  );
  previousTime = timestamp;

  accumulator += elapsed;

  input.poll();

  while (accumulator >= STEP) {
    game.fixedUpdate(STEP);
    accumulator -= STEP;
  }

  game.renderUpdate(accumulator / STEP);
  renderer.render(scene, camera);

  requestAnimationFrame(frame);
}

requestAnimationFrame(frame);
```

Maintain separate simulation transforms and rendered transforms to interpolate smoothly. Avoid interpolating across resets or teleports.

**Completion criteria:** The browser application loads, renders a scene, runs a stable fixed timestep and builds without errors.

#### 2.1 Trigger normalization

```js
function normalizeTrigger(raw) {
  const d = TUNING.triggerDeadzone;
  if (raw <= d) return 0;
  return (raw - d) / (1 - d);
}
```

#### 2.2 Stick normalization

Construct each 2D stick vector from its horizontal and vertical action strengths.

Clamp its length to 1, then apply a radial deadzone:

```js
function normalizeStick(x, y) {
  const magnitude = Math.min(Math.hypot(x, y), 1);
  const d = TUNING.stickDeadzone;

  if (magnitude <= d) return { x: 0, y: 0 };

  const scale =
    ((magnitude - d) / (1 - d)) /
    Math.hypot(x, y);

  return { x: x * scale, y: y * scale };
}
```

This must happen before combining left and right steering.

#### 2.3 Steering model

```js
const steering = clamp(
  (leftStick.x + rightStick.x) * 0.5,
  -1,
  1
);
```

Only the inside stick's downward input increases turning strength.

```js
let pullAmount = 0;

if (steering < 0) {
  pullAmount = Math.max(leftStick.y, 0);
} else if (steering > 0) {
  pullAmount = Math.max(rightStick.y, 0);
}

pullAmount *= smoothstep(0, 0.35, Math.abs(steering));

const yawRate =
  -steering * TUNING.turnSpeed
  - Math.sign(steering)
    * pullAmount
    * TUNING.downTurnBoost;
```

Apply yaw rotation before propulsion.

Positive steering must turn the craft right, matching the original coordinate and rotation convention.

Opposing stick inputs must cancel exactly.

#### 2.4 Propulsion

Brake reduces effective propulsion:

```js
const propulsion = throttle * (1 - brake);
```

When propulsion is active:

1. Determine the craft's world-space forward vector.
2. Add acceleration along forward.
3. Decompose horizontal velocity into forward and lateral components.
4. Apply exponential lateral grip.
5. Clamp horizontal velocity to maximum speed.

Reference equations:

```js
velocity += forward * acceleration * propulsion * dt;

along = forward * dot(velocity, forward);
sideways = velocity - along;

velocity =
  along +
  sideways * exp(-thrustGrip * propulsion * dt);

velocity = clampMagnitude(velocity, maxSpeed);
```

When propulsion is inactive:

```js
velocity = moveTowardVector(
  velocity,
  ZERO,
  coastDeceleration * dt
);
```

Apply braking afterward:

```js
velocity = moveTowardVector(
  velocity,
  ZERO,
  braking * brake * dt
);
```

Preserve momentum independently of facing direction. Releasing throttle must not force the craft to travel in the direction it is pointing.

#### 2.5 Suspension and gravity

Look one physics step ahead using the horizontal velocity.

Sample the road below:

```js
const samplePoint = position.clone()
  .addScaledVector(horizontalVelocity, dt);
```

From the source implementation:

- Ray begins 8 metres above the sample point.
- Ray ends 40 metres below it.
- Test the exact point first.
- If necessary, try four offsets of 0.04 m along ±X and ±Z.
- Only accept road collision surfaces, not barriers.

On road detection:

```js
targetY = hit.point.y + hoverHeight;

verticalVelocity = clamp(
  (targetY - position.y) * hoverResponse,
  -maxHoverVerticalSpeed,
  maxHoverVerticalSpeed
);
```

Without road detection:

```js
verticalVelocity -= 25 * dt;
```

Road normals drive visual slope orientation but must not directly modify horizontal propulsion or grip.

Implement collision-aware movement with sliding along road and barrier geometry. Avoid tunnelling at high speeds.

#### 2.6 Recovery

When the ship falls below `Y = -30`, reset to:

```js
position = [55, 2, 30];
rotation = [0, 0, 0];
velocity = [0, 0, 0];
```

Reset camera, vehicle visual state, hover animation phase, input-dependent visual effects and audio states.

**Completion criteria:** Vehicle acceleration, steering, momentum, braking, suspension and recovery match source-equivalent numerical tests.
